# 146. LRU 缓存

## 一、题目目标

设计一个满足 LRU（Least Recently Used，最近最少使用）策略的缓存，实现以下操作：

```python
get(key)
put(key, value)
```

- `get(key)`：如果 `key` 存在，返回对应的值，否则返回 `-1`。
- `put(key, value)`：插入或更新键值对。
- 当插入新键导致缓存超过容量时，删除最久没有被使用的键。
- `get` 和 `put` 操作都应尽量达到 `O(1)` 时间复杂度。

## 二、什么是“最近使用”？

只要一个键被成功访问或更新，它就会成为最近使用的键：

- `get(key)` 成功时，需要更新该键的使用顺序。
- `put(key, value)` 更新已有键时，也需要更新该键的使用顺序。
- `put(key, value)` 插入新键时，新键自然是最近使用的键。

可以把键的使用顺序表示为：

```text
最久未使用 ← [key1, key2, key3] → 最近使用
```

因此：

- 左端是需要优先淘汰的键。
- 右端是最近访问或更新的键。

## 三、示例过程

假设缓存容量为 `2`：

```python
cache = LRUCache(2)
```

依次执行：

```text
put(1, 1)
```

缓存状态：

```text
旧 ← [1] → 新
```

继续执行：

```text
put(2, 2)
```

缓存状态：

```text
旧 ← [1, 2] → 新
```

执行：

```text
get(1)
```

返回 `1`，同时键 `1` 成为最近使用的键：

```text
旧 ← [2, 1] → 新
```

执行：

```text
put(3, 3)
```

缓存已满，需要删除最久未使用的键 `2`：

```text
旧 ← [1, 3] → 新
```

此时：

```python
get(2)  # 返回 -1
```

## 方法一：哈希表 + Python 列表

## 四、数据结构设计

第一个实现使用两个容器：

```python
self.dict = {}
self.use = []
```

它们分别负责：

### 哈希表 `dict`

```text
key → value
```

作用是根据键快速查找对应的值。

例如：

```python
{
    1: 10,
    2: 20
}
```

### 列表 `use`

列表用于记录键的使用顺序：

```text
列表头部                 列表尾部
最久未使用 ← [1, 2, 3] → 最近使用
```

因此：

- `use[0]` 是最久未使用的键。
- `use[-1]` 是最近使用的键。

## 五、`get` 操作

```python
def get(self, key: int) -> int:
    if key in self.dict:
        index = self.use.index(key)
        self.use.pop(index)
        self.use.append(key)
        return self.dict[key]
    else:
        return -1
```

### 键不存在

```python
if key not in self.dict:
    return -1
```

缓存中没有这个键，直接返回 `-1`，使用顺序不发生变化。

### 键存在

如果键存在，需要完成两件事：

1. 返回对应的值。
2. 将该键更新为最近使用。

例如：

```text
use = [1, 2, 3]
get(2)
```

先找到并删除 `2`：

```text
[1, 3]
```

再把 `2` 添加到末尾：

```text
[1, 3, 2]
```

所以：

```python
index = self.use.index(key)
self.use.pop(index)
self.use.append(key)
```

## 六、`put` 操作

`put` 需要分为三种情况。

### 情况一：新键，且缓存未满

```python
if len(self.use) < self.capacity and key not in self.use:
    self.dict[key] = value
    self.use.append(key)
```

直接将键值对放入哈希表，并将新键添加到列表末尾。

例如：

```text
容量：3
当前：[1, 2]
插入：put(3, value)
结果：[1, 2, 3]
```

### 情况二：键已经存在

```python
elif key in self.use:
    self.dict[key] = value
    index = self.use.index(key)
    self.use.pop(index)
    self.use.append(key)
```

需要：

1. 更新键对应的值。
2. 从原来的使用位置删除该键。
3. 将它添加到末尾，表示最近使用。

例如：

```text
原顺序：[1, 2, 3]
执行：put(2, new_value)
新顺序：[1, 3, 2]
```

### 情况三：新键，且缓存已满

```python
else:
    del_key = self.use[0]
    self.use.pop(0)
    self.dict.pop(del_key)

    self.dict[key] = value
    self.use.append(key)
```

列表头部是最久未使用的键，所以先删除：

```python
del_key = self.use[0]
```

然后必须同时从两个容器中删除它：

```python
self.use.pop(0)
self.dict.pop(del_key)
```

最后插入新键，并把它放在使用顺序的末尾。

## 七、方法一的复杂度

哈希表查询虽然平均为 `O(1)`，但 Python 列表中的以下操作不是 `O(1)`：

```python
self.use.index(key)
self.use.pop(index)
self.use.pop(0)
key in self.use
```

原因是：

- `index` 和列表成员判断可能需要从头扫描列表。
- 删除中间或头部元素后，后面的元素需要整体向前移动。

设缓存容量为 `C`：

- `get` 时间复杂度：最坏 `O(C)`
- `put` 时间复杂度：最坏 `O(C)`
- 空间复杂度：`O(C)`

所以这种方法能够正确模拟 LRU，但不能满足题目要求的严格 `O(1)` 操作。

## 八、方法一的优缺点

优点：

- 思路直观。
- 容易通过列表观察使用顺序。
- 代码适合帮助理解 LRU 的基本规则。

缺点：

- 查找键在使用顺序中的位置需要 `O(C)`。
- 删除列表头部或中间元素需要移动其他元素。
- 缓存容量较大时效率较低。

## 方法二：哈希表 + 双向链表

## 九、为什么需要双向链表？

LRU 需要高效完成三种操作：

1. 根据 `key` 找到缓存节点。
2. 将任意节点移动到最近使用的位置。
3. 删除最久未使用的节点。

哈希表可以在平均 `O(1)` 时间内根据 `key` 找到节点：

```text
key → Node
```

双向链表可以在已经得到节点引用的情况下，在 `O(1)` 时间内删除该节点：

```text
node.prev ← node → node.next
```

两者结合后：

- 哈希表负责“快速找到节点”。
- 双向链表负责“快速维护使用顺序”。

## 十、节点结构

```python
class Node:
    def __init__(self, key=None, val=None, prev=None, next=None):
        self.key = key
        self.val = val
        self.prev = prev
        self.next = next
```

节点需要同时保存 `key` 和 `value`：

- `value` 用于 `get` 返回结果。
- `key` 用于淘汰节点时，从哈希表中删除对应记录。
- `prev` 和 `next` 用于在双向链表中连接前后节点。

如果节点只保存 `value`，淘汰链表节点时就不知道应该从哈希表中删除哪个键。

## 十一、双向链表结构

代码创建了两个哑节点：

```python
self.head = Node()
self.tail = Node()

self.head.next = self.tail
self.tail.prev = self.head
```

链表结构为：

```text
head ⇄ 最久未使用节点 ⇄ ... ⇄ 最近使用节点 ⇄ tail
```

其中：

- `head.next` 是最久未使用的真实节点。
- `tail.prev` 是最近使用的真实节点。
- `head` 和 `tail` 只是哑节点，不保存有效缓存数据。

### 两个哑节点的作用

哑节点使每个真实节点始终都有前驱和后继，因此删除节点时可以统一写成：

```python
node.prev.next = node.next
node.next.prev = node.prev
```

不需要单独判断：

- 被删除的是不是第一个节点；
- 被删除的是不是最后一个节点；
- 链表中是不是只有一个真实节点。

## 十二、方法二必须维护的不变量

实现过程中必须始终保证：

1. 哈希表中的每个键都对应双向链表中的一个真实节点。
2. 双向链表中的每个真实节点都能通过它的 `key` 在哈希表中找到。
3. 越靠近 `head` 的节点越久没有使用。
4. 越靠近 `tail` 的节点越新被使用。
5. `head.next` 是需要优先淘汰的节点。
6. `tail.prev` 是最近使用的节点。

LRU 的正确性依赖哈希表和链表状态始终同步。

## 十三、从双向链表中删除节点

已知节点 `node`：

```text
node.prev ⇄ node ⇄ node.next
```

删除它只需要让前后节点直接相连：

```python
node.prev.next = node.next
node.next.prev = node.prev
```

变化过程：

```text
删除前：
A ⇄ node ⇄ B

删除后：
A ⇄ B
```

因为已经通过哈希表得到了 `node`，所以不需要遍历链表寻找它，时间复杂度为 `O(1)`。

## 十四、在链表尾部添加节点

链表尾部代表最近使用的位置。假设需要把 `node` 放到 `tail` 前面：

```python
self.tail.prev.next = node
node.prev = self.tail.prev
node.next = self.tail
self.tail.prev = node
```

假设原链表为：

```text
... ⇄ A ⇄ tail
```

插入后：

```text
... ⇄ A ⇄ node ⇄ tail
```

四条指针更新分别表示：

```text
A.next = node
node.prev = A
node.next = tail
tail.prev = node
```

## 十五、方法二的 `get`

```python
def get(self, key: int) -> int:
    if key not in self.dict:
        return -1

    node = self.dict[key]

    # 从原位置删除
    node.prev.next = node.next
    node.next.prev = node.prev

    # 移动到链表尾部
    self.tail.prev.next = node
    node.prev = self.tail.prev
    node.next = self.tail
    self.tail.prev = node

    return node.val
```

### 键不存在

直接返回 `-1`，不修改链表。

### 键存在

成功访问意味着该节点刚刚被使用，因此需要：

1. 通过哈希表取得节点。
2. 从原位置删除节点。
3. 将节点添加到链表尾部。
4. 返回节点的值。

例如：

```text
原顺序：
head ⇄ 1 ⇄ 2 ⇄ 3 ⇄ tail

执行 get(2) 后：
head ⇄ 1 ⇄ 3 ⇄ 2 ⇄ tail
```

## 十六、方法二的 `put`

同样需要分三种情况。

### 情况一：插入新键，且缓存未满

```python
if len(self.dict) < self.capacity and key not in self.dict:
    node = Node(key, value, self.tail.prev, self.tail)
    self.dict[key] = node
    self.tail.prev.next = node
    self.tail.prev = node
```

新节点需要：

1. 放入哈希表。
2. 插入双向链表尾部。

它刚刚被插入，所以是最近使用的节点。

### 情况二：更新已有键

```python
elif key in self.dict:
    node = self.dict[key]
    node.val = value
```

先更新值，然后将节点从原位置移到链表尾部：

```python
node.prev.next = node.next
node.next.prev = node.prev

self.tail.prev.next = node
node.prev = self.tail.prev
node.next = self.tail
self.tail.prev = node
```

更新已有键也属于一次使用，因此需要刷新使用顺序。

### 情况三：插入新键，且缓存已满

最久未使用的节点是：

```python
node = self.head.next
```

首先记录它的键：

```python
old_key = node.key
```

然后从哈希表中删除：

```python
self.dict.pop(old_key)
```

再从双向链表中删除：

```python
node.prev.next = node.next
node.next.prev = node.prev
```

最后创建新节点，同时加入哈希表和链表尾部。

这里必须同时修改哈希表和链表，否则两个数据结构会失去同步。

## 十七、方法二的复杂度

设缓存容量为 `C`。

### `get`

- 哈希表查找节点：平均 `O(1)`
- 删除节点：`O(1)`
- 添加到链表尾部：`O(1)`

所以：

```text
get：平均 O(1)
```

### `put`

- 查询键是否存在：平均 `O(1)`
- 更新或插入哈希表：平均 `O(1)`
- 删除链表节点：`O(1)`
- 在尾部插入节点：`O(1)`

所以：

```text
put：平均 O(1)
```

### 空间复杂度

哈希表和双向链表最多保存 `C` 个真实节点：

```text
O(C)
```

## 十八、建议提取辅助方法

当前代码在 `get` 和 `put` 中多次重复“删除节点”和“添加到尾部”的指针操作。可以提取成辅助方法，降低写错指针的风险。

```python
def _remove(self, node):
    node.prev.next = node.next
    node.next.prev = node.prev

def _add_to_tail(self, node):
    last = self.tail.prev
    last.next = node
    node.prev = last
    node.next = self.tail
    self.tail.prev = node

def _move_to_tail(self, node):
    self._remove(node)
    self._add_to_tail(node)
```

这样，成功访问已有节点时只需要：

```python
node = self.dict[key]
self._move_to_tail(node)
```

淘汰最久未使用节点时：

```python
oldest = self.head.next
self._remove(oldest)
self.dict.pop(oldest.key)
```

代码的含义会更加清楚。

## 十九、两种方法对比

| 方法 | 值的查询 | 使用顺序 | `get` | `put` | 空间复杂度 |
| --- | --- | --- | --- | --- | --- |
| 哈希表 + 列表 | 哈希表 | Python 列表 | 最坏 `O(C)` | 最坏 `O(C)` | `O(C)` |
| 哈希表 + 双向链表 | 哈希表 | 双向链表 | 平均 `O(1)` | 平均 `O(1)` | `O(C)` |

第一种方法的重点是理解 LRU 规则：

> 使用列表头部表示最久未使用，列表尾部表示最近使用。

第二种方法的重点是解决效率问题：

> 哈希表负责在 `O(1)` 时间内定位节点，双向链表负责在 `O(1)` 时间内删除和移动节点。

## 二十、为什么不能只使用一种数据结构？

### 只使用哈希表

哈希表可以快速查询键值，但普通哈希表不能方便地维护和更新使用顺序，也不能直接知道谁最久没有被使用。

### 只使用双向链表

双向链表可以维护使用顺序，但根据 `key` 查找节点需要从头遍历，时间复杂度为 `O(C)`。

### 两者结合

```text
             根据 key 定位
哈希表 --------------------→ 节点
                              │
                              │ O(1) 删除、移动
                              ↓
                         双向链表
```

两种数据结构互相补足：

```text
哈希表解决“在哪里”
双向链表解决“如何快速移动”
```

## 二十一、代码中的注意事项

### 1. 两个 `LRUCache` 类同名

当前文件中定义了两个同名的：

```python
class LRUCache:
```

Python 会使用后面定义的类覆盖前面的类。因此，文件执行完以后，实际保留的是“哈希表 + 双向链表”的实现。

如果想在本地同时测试两个版本，可以改名为：

```python
class LRUCacheWithList:
    ...

class LRUCacheWithLinkedList:
    ...
```

提交到题目平台时，只保留准备提交的 `LRUCache` 即可。

### 2. 哈希表与链表必须同步

插入新节点时，两边都要添加：

```python
self.dict[key] = node
在链表尾部插入 node
```

淘汰旧节点时，两边都要删除：

```python
self.dict.pop(node.key)
从链表中删除 node
```

只修改其中一个数据结构会导致缓存状态错误。

### 3. 不要在移动节点时创建新节点

访问或更新已有键时，直接移动原节点即可。这样哈希表中保存的节点引用仍然有效：

```python
node = self.dict[key]
移动 node
```

### 4. 容量边界

题目通常保证：

```text
capacity >= 1
```

如果允许 `capacity == 0`，当前两个版本都需要额外处理，否则插入时可能访问不存在的真实节点或空列表元素。

## 二十二、总结

LRU 缓存的核心不是简单地存储键值，而是同时维护两个信息：

```text
1. key 对应什么 value？
2. key 最近什么时候被使用？
```

第一种方法使用：

```text
哈希表存值 + Python 列表记录顺序
```

它容易理解，但移动和删除列表元素需要 `O(C)` 时间。

第二种方法使用：

```text
哈希表定位节点 + 双向链表维护顺序
```

其中：

```text
head.next → 最久未使用节点
tail.prev → 最近使用节点
```

每次成功访问、更新或插入节点，都将节点移动到 `tail` 前；容量满时，删除 `head` 后的第一个真实节点。这样便可以使 `get` 和 `put` 都达到平均 `O(1)` 时间复杂度。
