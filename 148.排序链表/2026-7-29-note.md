# 148. 排序链表

## 题目核心

题目要求将链表按升序排列，并返回排序后的链表。

链表不能像数组一样通过下标快速访问中间位置，因此不适合直接使用数组中常见的快速排序。归并排序只需要顺序访问节点，非常适合链表。

归并排序主要分为两步：

1. 将链表不断拆成更短的链表
2. 将两个已经有序的链表合并

## 公共操作：合并两个有序链表

### 思路

使用哑节点 `dummy` 保存合并后链表的头部，再用指针 `cur` 指向新链表的尾节点。

比较 `left` 和 `right` 当前节点的值：

- 如果 `left.val < right.val`，将 `left` 接到 `cur` 后面
- 否则，将 `right` 接到 `cur` 后面
- 被选中的指针向后移动

当其中一条链表遍历结束后，另一条链表剩余的部分本身已经有序，可以直接接到结果链表末尾。

```python
def merge(left, right):
    dummy = ListNode(0)
    cur = dummy

    while left is not None and right is not None:
        if left.val < right.val:
            cur.next = left
            left = left.next
        else:
            cur.next = right
            right = right.next
        cur = cur.next

    cur.next = left if left is not None else right
    return dummy.next
```

合并两个总长度为 `n` 的链表：

- 时间复杂度：`O(n)`
- 额外空间复杂度：`O(1)`

这里没有创建保存节点的新链表，只是修改原节点的 `next` 指针。

## 方法一：自顶向下归并排序（递归）

### 思路

递归地将链表从中间分成左右两半，分别排序后，再合并两个有序链表。

完整过程为：

```text
寻找中点
   ↓
断开左右链表
   ↓
递归排序左半部分
   ↓
递归排序右半部分
   ↓
合并两个有序链表
```

### 如何寻找中点

使用快慢指针：

- `slow` 每次走一步
- `fast` 每次走两步

代码中让 `fast` 从 `head.next` 开始：

```python
slow = head
fast = head.next

while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
```

循环结束后，`slow` 指向左半部分的最后一个节点，`slow.next` 是右半部分的头节点。

然后必须断开链表：

```python
right_head = slow.next
slow.next = None
```

例如：

```text
4 → 2 → 1 → 3
```

会被拆成：

```text
4 → 2
1 → 3
```

继续递归拆分，直到每条链表只剩一个节点。单节点链表天然有序，然后开始逐层合并。

### 递归终止条件

```python
if head is None or head.next is None:
    return head
```

空链表和只有一个节点的链表不需要排序。

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(log n)`

每一层合并需要 `O(n)` 时间，共有 `log n` 层。虽然合并过程本身只使用 `O(1)` 额外空间，但递归调用栈需要 `O(log n)` 空间。

### 易错点

1. 必须执行 `slow.next = None`

   如果不将左右链表断开，递归时左半部分仍然连接着右半部分，无法正确缩小问题规模。

2. `fast` 从 `head.next` 开始

   这样在只有两个节点时，`slow` 会停在第一个节点，可以将链表正确拆成两个单节点链表。

3. 递归方法不满足严格的 `O(1)` 额外空间

   原因是递归调用栈占用 `O(log n)` 空间。

## 方法二：自底向上归并排序（迭代）

### 思路

递归方法是先不断拆分，再从底层开始合并。自底向上方法则直接从长度为 `1` 的有序子链表开始，两两合并。

子链表长度依次为：

```text
1 → 2 → 4 → 8 → ...
```

假设原链表为：

```text
4 → 2 → 1 → 3
```

第一轮，`sublength = 1`：

```text
[4] + [2] → [2 → 4]
[1] + [3] → [1 → 3]
```

链表变为：

```text
2 → 4 → 1 → 3
```

第二轮，`sublength = 2`：

```text
[2 → 4] + [1 → 3] → [1 → 2 → 3 → 4]
```

当 `sublength >= length` 时，整个链表已经有序。

### 指针含义

- `dummyHead`：哑节点，便于处理排序后头节点发生变化的情况
- `prev`：指向本轮已经合并部分的最后一个节点
- `curr`：指向下一组待拆分链表的起点
- `head1`：第一段子链表的头节点
- `head2`：第二段子链表的头节点
- `succ`：下一组尚未处理的链表头节点

每一组的处理过程是：

```text
从 curr 开始截取长度为 sublength 的 head1
                    ↓
再截取长度为 sublength 的 head2
                    ↓
保存剩余链表的起点 succ
                    ↓
合并 head1 和 head2
                    ↓
将合并结果接到 prev 后面
                    ↓
curr 移动到 succ，继续处理下一组
```

链表长度不一定正好是 `sublength` 的倍数，所以截取第二段链表时，需要判断 `curr` 是否为 `None`。

### 为什么需要保存 `succ`

截取第二段子链表时需要执行：

```python
curr.next = None
```

这会断开第二段链表与后续节点的连接。因此必须提前保存：

```python
succ = curr.next
```

否则会丢失后面尚未处理的链表。

### 为什么使用哑节点

每轮合并都可能改变链表的头节点，例如：

```text
4 → 2
```

合并后头节点变成 `2`。使用 `dummyHead` 后，只需要不断修改 `dummyHead.next`，最后返回：

```python
return dummyHead.next
```

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(1)`

一共有 `log n` 轮合并，每轮遍历全部节点，时间复杂度为 `O(n log n)`。整个过程只使用若干指针变量，没有递归调用栈，因此额外空间复杂度为 `O(1)`。

### 易错点

1. 截取子链表后要及时断开

   `head1`、`head2` 和后续链表之间必须断开，否则合并时可能把未处理的节点一起带入。

2. 第二段子链表可能不存在或长度不足

   遍历时必须先判断 `curr`，避免访问 `None.next`。

3. 合并后要让 `prev` 移动到合并链表的尾部

   ```python
   while prev.next:
       prev = prev.next
   ```

   否则无法正确连接下一组合并结果。

4. 每轮结束后子链表长度要翻倍

   ```python
   sublength <<= 1
   ```

   等价于：

   ```python
   sublength *= 2
   ```

## 两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
| --- | --- | --- | --- |
| 自顶向下归并排序 | `O(n log n)` | `O(log n)` | 代码直观，容易理解，但使用递归栈 |
| 自底向上归并排序 | `O(n log n)` | `O(1)` | 完全迭代，满足常数级额外空间要求，但指针处理更复杂 |

## 代码中的注意事项

当前文件在同一个 `Solution` 类中定义了两个同名的 `sortList` 方法。

在 Python 中，后定义的方法会覆盖前面的方法，因此实际调用：

```python
Solution().sortList(head)
```

时，只会执行第二个自底向上的迭代版本。第一个递归版本不会被调用。

如果想同时保留并测试两种方法，可以改成不同的方法名，例如：

```python
def sortListTopDown(self, head):
    ...

def sortListBottomUp(self, head):
    ...
```

## 我的理解总结

两种方法本质上都使用归并排序，核心都是“合并两个有序链表”。

自顶向下的方法通过快慢指针找到中点，不断递归拆分链表，再逐层合并。它更容易理解，但需要递归栈。

自底向上的方法省略了递归拆分过程，直接把单个节点看作有序链表，按照长度 `1、2、4、8……` 不断合并。它的指针操作更复杂，但额外空间复杂度可以达到 `O(1)`，更符合这道题的进阶要求。
