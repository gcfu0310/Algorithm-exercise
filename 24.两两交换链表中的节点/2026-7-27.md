# 24. 两两交换链表中的节点

## 递归解法

```python
def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
    if not head or not head.next:
        return head

    newHead = head.next
    head.next = self.swapPairs(newHead.next)
    newHead.next = head
    return newHead
```

这个递归解法最关键的思想是：

> 当前这一层只负责交换前两个节点，剩余链表交给同一个函数处理。

## 一、明确递归函数的“承诺”

理解递归时，不要一开始就钻进每一层调用。首先要明确这个函数的完整功能：

```python
swapPairs(head)
```

它的承诺是：

> 将从 `head` 开始的链表两两交换，并返回交换后链表的新头节点。

例如：

```text
swapPairs(1 → 2 → 3 → 4)
```

应该返回：

```text
2 → 1 → 4 → 3
```

有了这个承诺，处理当前链表时就不需要亲自处理后面的所有节点，只需要相信：

```python
self.swapPairs(newHead.next)
```

会把剩余链表正确处理好。

## 二、逐行理解代码

假设当前链表为：

```text
1 → 2 → 3 → 4
```

### 1. 递归终止条件

```python
if not head or not head.next:
    return head
```

如果链表中没有节点，或者只剩一个节点，就没有两个节点可以交换，直接返回即可。

```text
空链表 → 返回空链表
5      → 返回 5
```

这就是递归中的最小问题，也叫基本情况。

### 2. 保存第二个节点

```python
newHead = head.next
```

此时：

```text
head = 1
newHead = 2
```

之所以叫 `newHead`，是因为交换完成后，第二个节点 `2` 会移动到节点 `1` 前面，成为当前这段链表的新头节点。

### 3. 递归处理剩余链表

```python
head.next = self.swapPairs(newHead.next)
```

`newHead.next` 是节点 `3`，所以递归调用相当于：

```python
swapPairs(3 → 4)
```

根据函数的承诺，它会返回：

```text
4 → 3
```

然后把这个结果连接到节点 `1` 后面：

```text
1 → 4 → 3
```

交换之后，当前第一个节点会变成当前这一对中的第二个节点，所以它后面应该连接已经完成两两交换的剩余链表。

### 4. 交换当前两个节点

```python
newHead.next = head
```

让节点 `2` 指向节点 `1`：

```text
2 → 1 → 4 → 3
```

至此，当前两个节点交换完成。

### 5. 返回新的头节点

```python
return newHead
```

交换之前，这段链表的头节点是 `1`；交换之后变成了 `2`，所以应当返回 `newHead`。

## 三、完整递归过程

以链表 `1 → 2 → 3 → 4` 为例，递归调用不断缩小问题：

```text
swapPairs(1 → 2 → 3 → 4)
    swapPairs(3 → 4)
        swapPairs(None)
```

到达空链表后开始逐层返回。

### 最内层

```text
swapPairs(None)
```

触发终止条件，返回 `None`。

### 处理 `3 → 4`

当前层执行：

```python
newHead = 4
3.next = swapPairs(None)  # 3.next = None
4.next = 3
return 4
```

得到：

```text
4 → 3
```

### 处理 `1 → 2 → 3 → 4`

递归调用已经返回：

```text
4 → 3
```

当前层执行：

```python
newHead = 2
1.next = 4
2.next = 1
return 2
```

最终得到：

```text
2 → 1 → 4 → 3
```

整个过程可以概括为：

```text
当前两个节点：1 → 2
剩余部分：        3 → 4

递归处理剩余部分：
3 → 4  变成  4 → 3

当前层完成交换和连接：
2 → 1 → 4 → 3
```

## 四、为什么指针修改的顺序不能交换？

代码先执行：

```python
head.next = self.swapPairs(newHead.next)
```

然后才执行：

```python
newHead.next = head
```

如果先执行 `newHead.next = head`，原来的：

```text
1 → 2 → 3
```

就会变成：

```text
1 → 2
↑   ↓
└───┘
```

节点 `1` 和 `2` 会形成环，并且可能丢失通往节点 `3` 的指针。

因此，在改变 `newHead.next` 之前，必须先利用它找到并处理剩余链表。链表题中修改指针的顺序非常重要。

## 五、做算法题时如何思考递归？

可以依次回答下面五个问题。

### 1. 这个函数负责什么？

先用一句完整的话定义函数的功能。

本题中：

> `swapPairs(head)` 负责交换从 `head` 开始的整条链表，并返回交换后的新头节点。

不要将它定义成“交换前两个节点”，因为这个函数实际处理的是整条链表。

### 2. 最小规模的问题是什么？

问自己：

> 问题小到什么程度时，可以不再递归，直接得到答案？

本题中，空链表和只有一个节点的链表都不需要交换：

```python
if not head or not head.next:
    return head
```

### 3. 如何把问题缩小？

本题每次处理两个节点，剩余问题是：

```text
原问题：1 → 2 → 3 → 4
子问题：        3 → 4
```

对应：

```python
self.swapPairs(newHead.next)
```

递归调用必须使问题规模不断缩小，否则会导致无限递归。

### 4. 假设子问题已经解决，当前层做什么？

这是理解递归最重要的一步。

先假设递归调用已经能够返回正确结果：

```python
rest = self.swapPairs(newHead.next)
```

那么 `rest` 就是已经两两交换完成的剩余链表。当前层只需要完成两件事：

1. 让第一个节点连接处理好的剩余链表。
2. 让第二个节点指向第一个节点。

```python
head.next = rest
newHead.next = head
```

### 5. 当前层应该返回什么？

交换后：

```text
head → newHead
```

变为：

```text
newHead → head
```

新的头节点是 `newHead`，因此：

```python
return newHead
```

## 六、将这种思路用于其他题目

### 示例一：反转链表

首先定义函数承诺：

> `reverse(head)` 返回从 `head` 开始反转后的链表头节点。

将问题缩小：

```python
new_head = reverse(head.next)
```

假设后面的链表已经反转：

```text
原来：1 → 2 → 3 → 4
结果：    2 ← 3 ← 4
```

当前层只负责将节点 `1` 接到最后：

```python
def reverse(head):
    if not head or not head.next:
        return head

    new_head = reverse(head.next)
    head.next.next = head
    head.next = None
    return new_head
```

思考方式仍然是：

```text
剩余部分交给递归
→ 假设递归已经完成
→ 当前层只处理当前节点
```

### 示例二：二叉树的最大深度

函数承诺：

> `maxDepth(root)` 返回以 `root` 为根的二叉树的最大深度。

最小问题：

```python
if not root:
    return 0
```

缩小问题：

```python
left_depth = maxDepth(root.left)
right_depth = maxDepth(root.right)
```

假设左右子树的深度都已经求出，当前层只需要：

```python
return max(left_depth, right_depth) + 1
```

### 示例三：归并排序

函数承诺：

> `mergeSort(nums)` 返回排好序的数组。

处理过程：

1. 将数组分成左右两部分。
2. 相信递归能够分别排好左右两部分。
3. 当前层只负责合并两个有序数组。

```text
大问题：排序整个数组
子问题：排序左半部分、排序右半部分
当前层：合并两个有序结果
```

## 七、如何判断一道题是否适合递归？

如果一道题具有以下特征，可以考虑使用递归：

- 大问题和子问题具有相同的结构。
- 每次都能让问题规模明确缩小。
- 存在可以直接处理的最小情况。
- 子问题的结果能够组合成原问题的结果。

链表和二叉树尤其适合递归，因为它们本身就具有递归结构：

```text
链表 = 当前节点 + 剩余链表
二叉树 = 当前节点 + 左子树 + 右子树
```

## 八、递归思考模板

以后遇到递归题，可以先写下下面五个问题：

```text
1. 函数的完整功能是什么？
2. 什么时候可以直接返回？
3. 如何把原问题变成规模更小的同类问题？
4. 假设递归已经解决子问题，当前层还需要做什么？
5. 当前层最终应该返回什么？
```

对应的代码骨架是：

```python
def solve(problem):
    # 1. 处理最小问题
    if 满足终止条件:
        return 最小问题的答案

    # 2. 缩小问题，并相信递归结果
    sub_result = solve(更小的同类问题)

    # 3. 处理当前层
    result = 根据当前信息和 sub_result 构造答案

    # 4. 返回当前问题的答案
    return result
```

## 九、复习时要记住的核心

> 不要试图同时在脑中展开所有递归层。

先写清楚函数的承诺，然后把递归调用暂时看作一个已经可以正确工作的工具。你只负责思考：

1. 当前层拿到什么；
2. 当前层需要修改什么；
3. 当前层应该返回什么。

本题可以浓缩为一句话：

> 递归交换第三个节点开始的剩余链表，当前层再交换前两个节点，并把两部分连接起来。

## 十、复杂度

- 时间复杂度：`O(n)`，每个节点只会被处理一次。
- 空间复杂度：`O(n)`，递归调用栈最多保存约 `n / 2` 层，忽略常数后为 `O(n)`。
