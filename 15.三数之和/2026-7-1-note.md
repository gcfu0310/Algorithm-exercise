## 15. 三数之和

### 方法：排序 + 双指针

#### 1. 为什么先排序

题目要求找出所有“不重复”的三元组，使得三个数的和为 `0`。  
遇到“不重复”的组合问题时，可以优先考虑排序，因为排序后相同的数字会相邻，方便在遍历过程中跳过重复元素。

#### 2. 朴素思路：三层循环

最直观的做法是使用三层循环：

- 第一层循环确定第一个数 `a`；
- 第二层循环确定第二个数 `b`；
- 第三层循环确定第三个数 `c`。

为了避免重复，当前循环使用的数字不能和同一层循环中上一次使用的数字相同。  
例如，只有当 `a == 0` 或 `nums[a] != nums[a - 1]` 时，才开始枚举第二个数 `b`；第二层和第三层循环同理。

这种做法的时间复杂度是 `O(n^3)`，虽然思路直接，但效率较低。

#### 3. 双指针优化

排序之后，可以固定第一个数 `a`，然后用双指针寻找另外两个数：

- `b` 指向 `a` 后面的第一个位置；
- `c` 指向数组末尾；
- 三个数始终满足位置关系：`a < b < c`。

当 `a` 固定时，我们要找到满足：

```text
nums[a] + nums[b] + nums[c] == 0
```

的 `b` 和 `c`。

因为数组已经有序：

- 如果当前和大于 `0`，说明整体偏大，需要让 `c` 左移，使第三个数变小；
- 如果当前和小于 `0`，说明整体偏小，需要让 `b` 右移，使第二个数变大；
- 如果当前和等于 `0`，就记录这一组三元组，然后继续移动指针寻找下一组结果。

这样可以把原来枚举 `b` 和 `c` 的两层循环，优化成一次相向移动的双指针扫描。

#### 4. 为什么 `c` 不需要每次重新回到最右边

需要注意的是，右指针 `c` 应该在固定 `a` 之后初始化到数组末尾，而不是在每次移动 `b` 时都重新初始化。

原因是：当 `b` 向右移动时，`nums[b]` 只会变大。如果之前为了让三数之和不大于 `0`，已经把 `c` 向左移动过，那么在新的、更大的 `b` 下，`c` 更没有必要回到更靠右、更大的位置。

如果每次都让 `c` 从最右边重新开始移动，就会产生很多重复计算，双指针的优化效果也会被破坏。

#### 5. 去重细节

去重主要有两处：

- 固定 `a` 时，如果 `nums[a] == nums[a - 1]`，说明这个数已经作为第一个数处理过，应该跳过；
- 找到一组三元组后，移动 `b` 和 `c` 时，也要跳过和上一次相同的值，避免得到重复答案。

排序的作用不只是方便移动双指针，也让这些重复元素可以集中在一起，从而更容易跳过。

#### 6. 终止条件

当 `b` 和 `c` 重合时，说明已经不存在满足 `a < b < c` 的组合了，此时应该结束当前这一轮搜索。

#### 7. 复杂度

- 排序的时间复杂度是 `O(n log n)`；
- 外层固定 `a` 需要 `O(n)`；
- 每次固定 `a` 后，`b` 和 `c` 最多整体移动 `O(n)` 次。

因此，总时间复杂度是 `O(n^2)`，空间复杂度通常为 `O(1)`，不考虑排序本身可能使用的额外空间。
