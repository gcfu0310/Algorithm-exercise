# 23. 合并 K 个升序链表

## 题目目标

给定一个链表数组 `lists`，其中每条链表都已经按照升序排列，将它们合并成一条升序链表并返回。

例如：

```text
lists = [
    1 → 4 → 5,
    1 → 3 → 4,
    2 → 6
]
```

合并结果：

```text
1 → 1 → 2 → 3 → 4 → 4 → 5 → 6
```

本题的基础操作是“合并两条升序链表”，然后思考如何利用这个基础操作合并 `k` 条链表。

## 基础操作：合并两条升序链表

两种方法都使用了相同的 `merge` 函数：

```python
def merge(head1, head2):
    dummy = ListNode(0)
    cur = dummy

    while head1 and head2:
        if head1.val < head2.val:
            cur.next = head1
            head1 = head1.next
        else:
            cur.next = head2
            head2 = head2.next

        cur = cur.next

    cur.next = head1 if head1 else head2
    return dummy.next
```

### 函数承诺

> `merge(head1, head2)` 将两条升序链表合并为一条升序链表，并返回合并结果的头节点。

### 为什么每次选择较小的节点？

因为两条链表本身已经有序，所以它们当前头节点中的较小者，一定是所有剩余节点中的最小值，可以直接接到结果链表末尾。

例如：

```text
head1：1 → 4 → 5
head2：2 → 3 → 6
```

第一次比较 `1` 和 `2`，选择 `1`：

```text
结果：1
head1：4 → 5
head2：2 → 3 → 6
```

第二次比较 `4` 和 `2`，选择 `2`：

```text
结果：1 → 2
head1：4 → 5
head2：3 → 6
```

持续进行，最终得到：

```text
1 → 2 → 3 → 4 → 5 → 6
```

### 哑节点的作用

```python
dummy = ListNode(0)
cur = dummy
```

哑节点让第一个节点和后续节点使用相同的连接方式：

```python
cur.next = 选中的节点
```

因此不需要单独判断结果链表是否为空。合并结束后，真正的头节点是：

```python
dummy.next
```

### 为什么可以一次连接剩余部分？

当循环结束时，至少有一条链表已经为空：

```python
cur.next = head1 if head1 else head2
```

另一条链表剩余部分本身已经有序，而且其中所有节点都不小于当前结果的最后一个节点，所以可以直接整体连接，不需要继续逐个比较。

### 复杂度

假设两条链表的长度分别是 `m` 和 `n`：

- 时间复杂度：`O(m + n)`
- 额外空间复杂度：`O(1)`

代码没有创建新的数据节点，只是改变原链表节点之间的指向。

---

## 方法一：顺序合并

### 核心思路

先把前两条链表合并，再用合并结果与第三条链表合并，如此重复，直到处理完所有链表。

```python
ans = lists[0]

for i in range(1, len(lists)):
    ans = merge(ans, lists[i])

return ans
```

### 函数承诺

执行到第 `i` 次循环后：

> `ans` 是 `lists[0]` 到 `lists[i]` 的合并结果。

### 执行过程

假设有四条链表：

```text
L1、L2、L3、L4
```

合并顺序为：

```text
ans1 = merge(L1, L2)
ans2 = merge(ans1, L3)
ans3 = merge(ans2, L4)
```

结构上相当于：

```text
(((L1 + L2) + L3) + L4)
```

### 边界情况

当数组为空时：

```python
if len(lists) == 0:
    return None
```

当数组只有一条链表时：

```python
ans = lists[0]
```

循环不会执行，直接返回这条链表。

数组中的某一项也可能是空链表，但不需要特殊处理，因为 `merge` 可以正确合并空链表：

```text
merge(None, L1) → L1
```

### 时间复杂度

假设有 `k` 条链表，每条链表平均包含 `n` 个节点，总节点数为：

```text
N = k × n
```

顺序合并时：

```text
第一次合并大约处理 2n 个节点
第二次合并大约处理 3n 个节点
第三次合并大约处理 4n 个节点
……
最后一次合并大约处理 kn 个节点
```

总操作量约为：

```text
2n + 3n + 4n + ... + kn
```

因此：

- 使用 `k` 和平均长度 `n` 表示：`O(k²n)`
- 使用总节点数 `N` 表示：最坏为 `O(kN)`
- 额外空间复杂度：`O(1)`

### 优点与缺点

优点：

- 思路直接，代码容易理解。
- 只需要复用两条链表的合并函数。
- 不需要递归栈。

缺点：

- 前面已经合并得到的长链表会被反复遍历。
- 当 `k` 较大时，效率不如分治合并。

## 方法二：分治合并

### 核心思路

将 `k` 条链表不断分成左右两部分：

1. 递归合并左半部分。
2. 递归合并右半部分。
3. 将左右两部分的结果合并。

```python
def merged(lists, left, right):
    if left == right:
        return lists[left]

    if left > right:
        return None

    mid = (left + right) // 2

    left_result = merged(lists, left, mid)
    right_result = merged(lists, mid + 1, right)

    return merge(left_result, right_result)
```

最终调用：

```python
return merged(lists, 0, len(lists) - 1)
```

### 递归函数的承诺

> `merged(lists, left, right)` 将下标从 `left` 到 `right` 的所有升序链表合并，并返回合并后的头节点。

理解递归时，可以先相信左右两次递归调用能够兑现这个承诺：

```python
left_result = merged(lists, left, mid)
right_result = merged(lists, mid + 1, right)
```

当前这一层只负责：

```python
merge(left_result, right_result)
```

也就是把左右两部分的结果合并起来。

### 递归终止条件

#### 区间中只有一条链表

```python
if left == right:
    return lists[left]
```

一条升序链表不需要继续合并，直接返回。

#### 区间中没有链表

```python
if left > right:
    return None
```

例如 `lists` 为空时，初始调用为：

```python
merged(lists, 0, -1)
```

此时 `left > right`，返回 `None`。

### 执行过程

假设有四条链表：

```text
L1、L2、L3、L4
```

分治过程为：

```text
              [L1, L2, L3, L4]
                 /          \
            [L1, L2]      [L3, L4]
             /    \        /    \
           L1      L2    L3      L4
             \    /        \    /
           merge12        merge34
                 \          /
               merge(merge12, merge34)
```

也可以表示为：

```text
merge(
    merge(L1, L2),
    merge(L3, L4)
)
```

与顺序合并相比，分治方法尽量让每次参与合并的两条链表长度接近。

### 为什么分治更快？

在顺序合并中：

```text
L1 和 L2 合并后的长链表
还要继续与 L3、L4……逐一合并
```

已经处理过的节点可能被反复遍历很多次。

分治合并形成一棵平衡的合并树。每一层中，所有合并操作处理的节点总数约为 `N`；树的高度约为 `log k`，所以总时间复杂度为：

```text
O(N log k)
```

其中：

- `N` 是所有链表的节点总数。
- `k` 是链表数量。

### 复杂度

- 时间复杂度：`O(N log k)`
- 递归调用栈空间：`O(log k)`

这里只计算额外空间。合并过程本身复用原链表节点，不需要创建长度为 `N` 的新链表。

---

## 两种方法对比

| 方法 | 合并结构 | 时间复杂度 | 额外空间复杂度 | 特点 |
| --- | --- | --- | --- | --- |
| 顺序合并 | 从左到右逐一合并 | 最坏 `O(kN)` | `O(1)` | 容易理解，但长链表会被反复遍历 |
| 分治合并 | 两两合并，形成平衡结构 | `O(N log k)` | `O(log k)` | 链表较多时效率更高 |

其中：

- `k` 表示链表数量。
- `N` 表示所有链表的节点总数。

## 分治递归的思考方法

可以按照下面五个问题分析。

### 1. 函数的功能是什么？

```text
merged(lists, left, right)
```

负责合并 `[left, right]` 范围内的全部链表，并返回合并后的头节点。

### 2. 最小问题是什么？

区间中只有一条链表：

```python
if left == right:
    return lists[left]
```

区间为空：

```python
if left > right:
    return None
```

### 3. 如何缩小问题？

从中点将区间分为两半：

```python
mid = (left + right) // 2
```

子问题分别是：

```text
[left, mid]
[mid + 1, right]
```

### 4. 假设子问题已经解决，当前层做什么？

假设左右两半都已经分别合并为一条有序链表，当前层只需要调用：

```python
merge(left_result, right_result)
```

### 5. 当前层返回什么？

返回左右两条有序链表合并后的新头节点。

## 易错点

### 1. 导入类型注解

函数签名使用了：

```python
lists: List[Optional[ListNode]]
```

因此本地运行时需要同时导入 `List`：

```python
from typing import List, Optional
```

当前代码只导入了 `Optional`。如果运行环境没有预先提供 `List`，定义 `Solution` 类时会出现 `NameError`。

### 2. 空数组的下标范围

当 `lists` 为空时：

```python
left = 0
right = -1
```

所以必须有：

```python
if left > right:
    return None
```

### 3. 中点和左右区间

```python
mid = (left + right) // 2
```

左右区间必须写成：

```python
[left, mid]
[mid + 1, right]
```

这样既不会遗漏链表，也不会重复处理同一条链表。

### 4. 移动 `cur` 和原链表指针

每次连接一个节点后，需要同时完成：

```python
cur = cur.next
head1 = head1.next
```

或者：

```python
cur = cur.next
head2 = head2.next
```

一个负责移动结果链表的尾指针，另一个负责移动被选中的原链表指针。

### 5. 相等时选择哪一条链表？

代码使用：

```python
if head1.val < head2.val:
```

当值相等时会选择 `head2`。这不会影响最终链表的升序性质。

如果希望相等时优先使用 `head1`，可以写成：

```python
if head1.val <= head2.val:
```

### 6. Python 中同名方法会被覆盖

当前代码在同一个 `Solution` 类中定义了两个同名的：

```python
def mergeKLists(...)
```

Python 不会同时保留这两个实现，后面的“分治合并”会覆盖前面的“顺序合并”。实际调用：

```python
Solution().mergeKLists(lists)
```

只会执行最后定义的分治版本。

如果想在本地同时测试两种方法，可以使用不同的方法名：

```python
def mergeKListsSequential(self, lists):
    ...

def mergeKListsDivideAndConquer(self, lists):
    ...
```

提交到题目平台时，只保留准备提交的那个 `mergeKLists` 即可。

## 总结

这两种方法的共同基础是：

> 先掌握如何合并两条升序链表，再决定以什么顺序重复使用这个操作。

顺序合并的思路是：

> 将当前合并结果依次与下一条链表合并。

分治合并的思路是：

> 将链表数组分成两半，分别递归合并，再合并左右两个结果。

当链表数量较多时，分治合并通过减少节点被重复遍历的次数，将时间复杂度从最坏 `O(kN)` 优化到 `O(N log k)`。
