# 35. 搜索插入位置

## 今日总结

这题用的是很经典的二分查找，不是二叉树查找。感觉很像高中算法题里那种“每次从中间切一半”的思路。

## 核心思路：二分查找

数组 `nums` 已经按升序排列，所以不需要从左到右一个一个找，可以每次检查中间位置 `k`。

- 如果 `target > nums[k]`，说明目标值或者插入位置一定在右半边，所以令 `i = k + 1`。
- 如果 `target <= nums[k]`，说明目标值或者插入位置可能在 `k`，也可能在左半边，所以令 `j = k`。

最后当 `i == j` 时，搜索区间为空，这个位置就是目标值应该插入的位置。

## 指针含义

这份代码使用的是左闭右开区间 `[i, j)`：

- `i`：当前搜索区间的左边界。
- `j`：当前搜索区间的右边界，但不包含 `j`。
- `k = (i + j) // 2`：当前搜索区间的中点。

一开始：

```python
i = 0
j = len(nums)
```

因为插入位置可能在数组最后面，所以 `j` 初始化为 `len(nums)`，而不是 `len(nums) - 1`。

## 为什么是 `O(log n)`

每次循环都会把搜索范围缩小一半：

```text
n -> n/2 -> n/4 -> n/8 -> ... -> 1
```

所以循环次数不是 `n` 次，更不是 `n^2` 次，而是 `log(n)` 级别。

## 关于 `if`

这份代码里用了两个 `if`：

```python
if target > nums[k]:
    i = k + 1
if target <= nums[k]:
    j = k
```

这样能跑通，但第二个判断其实和第一个判断互斥，用 `else` 或 `elif` 会更清晰，也少做一次判断：

```python
if target > nums[k]:
    i = k + 1
else:
    j = k
```

不过要注意：`if` 多并不会让空间复杂度变高。空间复杂度主要看有没有额外开数组、哈希表、递归栈等。这里只用了几个变量，所以空间复杂度仍然是 `O(1)`。

## 复杂度

- 时间复杂度：`O(log n)`，因为每次都把搜索范围缩小一半。
- 空间复杂度：`O(1)`，只使用了 `i`、`j`、`k` 这几个变量。
