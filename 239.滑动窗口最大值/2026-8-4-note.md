# LeetCode 239：滑动窗口最大值——从朴素窗口到单调队列

## 1. 问题描述

给定整数数组 `nums` 和窗口大小 `k`，让一个长度为 `k` 的窗口从数组左端开始，每次向右移动一个位置。需要输出每个窗口中的最大值。

例如：

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

窗口及最大值依次为：

```text
[1, 3, -1]   -> 3
[3, -1, -3]  -> 3
[-1, -3, 5]  -> 5
[-3, 5, 3]   -> 5
[5, 3, 6]    -> 6
[3, 6, 7]    -> 7
```

所以输出为：

```text
[3, 3, 5, 5, 6, 7]
```

## 2. 朴素滑动窗口思路

最直观的做法是用一个普通列表保存窗口中的全部元素：

1. 先把前 `k` 个元素放入列表；
2. 窗口右移时，删除列表最左边的元素；
3. 把新进入窗口的元素添加到列表右边；
4. 使用 `max()` 求当前窗口的最大值。

原始实现还缓存了上一个最大值，希望在它仍位于窗口中时避免重复调用 `max()`：

```python
class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        ans = []
        n = len(nums)
        queue = []

        for i in range(k):
            queue.append(nums[i])

        max_num = max(queue)
        ans.append(max_num)

        for i in range(k, n):
            queue.pop(0)
            queue.append(nums[i])

            if nums[i] > max_num:
                max_num = nums[i]
            elif nums[i] < max_num and max_num in queue:
                ans.append(max_num)
                continue
            else:
                max_num = max(queue)

            ans.append(max_num)

        return ans
```

其中几个关键操作的复杂度如下：

| 操作 | 时间复杂度 | 原因 |
| --- | ---: | --- |
| `queue.pop(0)` | `O(k)` | 删除列表首元素后，后面的元素都要整体向前移动 |
| `max_num in queue` | `O(k)` | 最坏情况下要顺序检查整个窗口 |
| `max(queue)` | `O(k)` | 必须遍历整个窗口才能确定最大值 |

虽然缓存最大值能减少某些情况下的重复计算，但最坏情况下，每移动一次窗口仍可能执行若干个 `O(k)` 操作。窗口大约移动 `n` 次，因此总时间复杂度仍为：

```text
O(nk)
```

这正是数据规模较大时容易超出时间限制的主要原因。真正需要优化的问题是：**能否不保存和反复扫描那些已经不可能成为最大值的元素？**

## 3. 优化过程中的核心观察

假设当前仍有竞争力的候选值为：

```text
[5, 3, 2]
```

现在新元素 `4` 从右侧进入窗口。`3` 和 `2` 可以立刻被淘汰，因为 `4`：

- 比 `3` 和 `2` 更大；
- 比它们更晚进入窗口；
- 因而也会比它们更晚离开窗口。

只要 `4` 仍在窗口内，较小且更早离开的 `3` 和 `2` 就绝不可能成为最大值。因此候选队列可直接变成：

```text
[5, 4]
```

这给出了优化的核心：

> 不保存窗口中的所有元素，只保存当前或未来仍可能成为窗口最大值的元素。

候选值按照从大到小排列，最大候选值自然位于最前面，于是无需每次用 `max()` 扫描整个窗口。

## 4. 为什么队列中保存下标，而不是元素值

只保存值可以比较大小，却无法分辨它来自数组的哪个位置，也就无法判断它何时离开窗口。保存下标则同时解决两个问题：

1. 用 `nums[index]` 取得值并比较大小；
2. 用 `index` 判断该元素是否仍在当前窗口内。

遍历到下标 `i` 时，当前窗口的下标范围为：

```text
[i - k + 1, i]
```

如果队首下标满足：

```python
queue[0] < i - k + 1
```

它位于窗口左边界之外，已经过期，应当删除。该判断也可以等价写成：

```python
queue[0] <= i - k
```

例如 `i = 4`、`k = 3` 时，窗口范围是 `[2, 4]`，下标 `1` 满足 `1 < 2`，因此已经离开窗口。

## 5. 单调队列的定义

本题中的 `queue` 是一个单调队列，具有以下性质：

- 保存的是数组下标，而不是元素值；
- 下标从队首到队尾递增，符合元素进入窗口的先后顺序；
- 下标对应的元素值从队首到队尾单调递减；
- 队首对应的值始终是当前窗口的最大值。

即：

```text
nums[queue[0]] >= nums[queue[1]] >= nums[queue[2]] >= ...
```

> 单调队列不保存窗口中的全部元素，只保存“当前或未来仍可能成为最大值”的元素下标。

## 6. 每轮遍历的四个步骤

### 第一步：删除过期队首

```python
if queue and queue[0] < i - k + 1:
    queue.popleft()
```

下标按照遍历顺序进入队尾，所以队列中的下标递增。最早进入、最早可能过期的下标只会在队首，因此检查队首即可。

这里使用 `if` 已经足够：每轮只向右移动一个位置，在上一轮队列合法的前提下，本轮最多只会新增一个过期下标。

### 第二步：删除较小队尾

```python
while queue and nums[queue[-1]] <= nums[i]:
    queue.pop()
```

当前值若大于或等于队尾值，队尾元素既更小（或相等），又更早离开窗口，已经失去竞争力，可以删除。

这里必须使用 `while`，不能只用 `if`。例如：

```text
队列对应值：[9, 7, 5, 3]
新元素：8
```

需要连续从队尾删除 `3`、`5`、`7`，遇到大于 `8` 的 `9` 才停止，最后得到：

```text
[9, 8]
```

若只用一次 `if`，只能删除 `3`，结果会是：

```text
[9, 7, 5, 8]
```

它已经不再单调递减。

因为队列原本有序，所以不必从头逐个比较：只需不断检查队尾；一旦队尾值大于当前值，更靠前的值只会更大，也就可以立即停止。

### 第三步：当前下标入队

```python
queue.append(i)
```

删除所有失去竞争力的队尾后，将当前下标放入队尾。此时下标仍递增，值仍单调递减。

### 第四步：记录窗口最大值

```python
if i >= k - 1:
    ans.append(nums[queue[0]])
```

只有完整窗口形成后才能记录答案。因为数组下标从 `0` 开始，当 `k = 3` 时，第一个完整窗口的下标是：

```text
0, 1, 2
```

所以遍历到 `i = 2 = k - 1` 时就应记录第一个答案。若写成 `i >= k`，会漏掉第一个窗口。

### 最终实现

```python
from collections import deque
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        ans = []
        queue = deque()  # 保存仍可能成为最大值的数组下标
        i = 0
        n = len(nums)

        while i < n:
            # 当前窗口左边界为 i - k + 1；删除已经离开窗口的队首下标
            if queue and queue[0] < i - k + 1:
                queue.popleft()

            # 当前元素更大且更晚离开窗口，因此较小或相等的旧队尾已失去竞争力
            while queue and nums[queue[-1]] <= nums[i]:
                queue.pop()

            # 当前下标入队；队列对应值仍保持单调递减
            queue.append(i)

            # i = k - 1 时第一个完整窗口形成，队首就是当前窗口最大值
            if i >= k - 1:
                ans.append(nums[queue[0]])

            i += 1

        return ans
```

## 7. 为什么窗口没有达到 `k` 时也要维护队列

单调队列必须从 `i = 0` 开始维护。即使当前元素数量还不到 `k`，也仍然要：

- 删除已经失去竞争力的队尾；
- 把当前下标加入队列。

区别仅在于：窗口未完整形成时，不能把队首值加入答案。

例如 `nums = [1, 3, -1]`、`k = 3`。处理 `1` 后队列为 `[0]`；处理 `3` 时先淘汰下标 `0`，再加入下标 `1`。等处理完 `-1`，第一个完整窗口的候选关系已经维护好，可以直接从队首取得 `3`。

因此无需为 `i < k - 1` 另写 `else`：

```python
while i < n:
    # 无论窗口是否完整，都维护单调队列

    if i >= k - 1:
        # 只有窗口完整后才记录答案

    i += 1
```

## 8. `<` 和 `<=` 的区别

维护队尾时有两种正确写法：

```python
while queue and nums[queue[-1]] < nums[i]:
```

使用 `<` 会保留值相等的多个下标。

```python
while queue and nums[queue[-1]] <= nums[i]:
```

使用 `<=` 会删除旧的相等下标，只留下更新的下标。

假设 `nums[2] = 5`、`nums[4] = 5`。二者提供的最大值相同，但下标 `4` 更晚进入，也会更晚离开窗口。只要旧的 `5` 仍在窗口中，新的 `5` 也一定在；旧下标没有不可替代的作用，所以通常推荐使用 `<=`。

> 值相同时，保留更新的下标，因为它能在窗口中存活更久。

使用 `<` 仍会得到正确答案，只是队列可能保留更多重复值对应的下标。

## 9. 两个删除步骤能否交换顺序

两类删除分别解决不同问题：

```python
# 删除窗口范围外的下标
if queue and queue[0] < i - k + 1:
    queue.popleft()

# 删除被当前元素淘汰的下标
while queue and nums[queue[-1]] <= nums[i]:
    queue.pop()
```

在本算法中，通常交换它们也不会影响最终答案：过期下标本来就不能提供答案；失去竞争力的下标也不会再提供答案。若一个过期下标先被第二步从队尾淘汰，也同样达到了删除它的结果。

不过更推荐原顺序：

1. 先保证队列中的下标属于当前窗口；
2. 再处理当前元素带来的大小关系变化。

这样每一步的职责清楚，也更便于检查队列不变量。

## 10. `deque` 数据类型介绍

```python
from collections import deque
```

`deque` 是 **double-ended queue（双端队列）**，能够高效地在队首和队尾添加或删除元素。本题既要从队首删除过期下标，又要从队尾删除失去竞争力的下标，因此它非常合适。

本题使用的操作：

```python
queue.append(i)      # 从队尾添加，O(1)
queue.pop()          # 从队尾删除，O(1)
queue.popleft()      # 从队首删除，O(1)
queue[0]             # 查看队首，O(1)
queue[-1]            # 查看队尾，O(1)
```

与普通列表对比：

```python
some_list.append(x)  # 通常为 O(1)
some_list.pop()      # O(1)
some_list.pop(0)     # O(n)，后续元素需要整体前移
```

`set` 不能替代 `deque`，因为：

- `set` 不维护本题所需的队列顺序；
- 它无法表达明确的队首和队尾；
- 它不能维护从队首到队尾单调递减的结构；
- 它不能按照进入窗口的先后顺序删除过期下标。

## 11. 完整示例推演

使用：

```text
nums = [1, 3, -1, -3, 5]
k = 3
```

下表中的“队列中的下标”才是 `queue` 真正保存的内容；“队列对应值”只是通过 `nums[index]` 得到的辅助展示。表中的队列状态均为完成本轮维护之后的状态。

| `i` | 当前值 | 当前窗口 | 本轮关键变化 | 队列中的下标 | 队列对应值 | 当前答案 |
| ---: | ---: | --- | --- | --- | --- | --- |
| 0 | 1 | `[1]`（未完整） | 下标 `0` 入队 | `[0]` | `[1]` | `[]` |
| 1 | 3 | `[1, 3]`（未完整） | `3 >= 1`，弹出 `0`；加入 `1` | `[1]` | `[3]` | `[]` |
| 2 | -1 | `[1, 3, -1]` | `-1 < 3`，直接加入 `2` | `[1, 2]` | `[3, -1]` | `[3]` |
| 3 | -3 | `[3, -1, -3]` | 队首 `1` 未过期；加入 `3` | `[1, 2, 3]` | `[3, -1, -3]` | `[3, 3]` |
| 4 | 5 | `[-1, -3, 5]` | `1` 先过期；`5` 再淘汰 `3`、`2`；加入 `4` | `[4]` | `[5]` | `[3, 3, 5]` |

以 `i = 4` 为例，当前窗口范围是 `[2, 4]`：

1. 队首下标 `1 < 2`，先删除过期下标 `1`；
2. 新值 `5` 依次淘汰队尾值 `-3` 和 `-1`；
3. 下标 `4` 入队；
4. 队首值 `nums[4] = 5` 就是当前窗口最大值。

## 12. 时间和空间复杂度

代码中虽然有嵌套的 `while`，但不能简单地把复杂度判断为 `O(n²)`。从每个下标的一生来看：

- 最多加入队列一次；
- 加入后，最多从队尾被淘汰一次；
- 如果没有从队尾淘汰，则最多从队首因过期被删除一次。

同一个下标一旦删除就不会重新入队，所以全部队列操作的总次数与 `n` 成正比。这就是算法能在线性时间内完成的原因。

```text
时间复杂度：O(n)
空间复杂度：O(k)
```

队列只保留当前窗口中的候选下标，长度不会超过窗口大小 `k`。

## 13. 常见错误总结

1. **使用 `list.pop(0)`**：删除首元素需要移动后续元素，单次为 `O(k)`。
2. **队列中只保存值**：遇到重复值时无法判断具体哪个元素已经过期。
3. **窗口形成后才开始维护队列**：前 `k - 1` 个元素之间的候选关系没有建立。
4. **忘记执行 `i += 1`**：`while i < n` 的条件不会变化，导致死循环。
5. **删除较小队尾时使用 `if`**：一次可能需要淘汰多个元素，必须使用 `while`。
6. **把记录条件写成 `i >= k`**：会漏掉在 `i = k - 1` 时形成的第一个窗口。
7. **未判空就访问 `queue[0]` 或 `queue[-1]`**：空队列访问会触发 `IndexError`。
8. **拼错 `nums`**：变量名不一致会触发 `NameError`，应保持代码中的拼写统一。
9. **误以为 `set` 能替代 `deque`**：集合无法维护所需的队首、队尾和单调顺序。
10. **误以为单调队列保存全部窗口元素**：失去竞争力的值会被提前删除，队列仅保存最大值候选下标。

## 14. 最终记忆总结

> 单调队列保存的不是窗口中的所有元素，而是仍有机会成为最大值的元素下标。队首负责提供答案，队尾负责淘汰较小元素，下标负责判断元素是否过期。

四步口诀：

```text
先删过期队首，
再删较小队尾，
当前下标入队，
窗口形成取队首。
```
